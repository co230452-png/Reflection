Second Week • August 8, 2026

Security Threats and Social Engineering Techniques and Psychological Tactic

This week, I learned about the 12 categories of threats to information security and how threats are not limited to hacking or malware. They can also come from human errors, technical failures, natural disasters, theft, and other factors. It reframed how I think about security risk — not as a single adversary trying to break in, but as a much wider range of things that can go wrong, many of which have nothing to do with an attacker at all.

I also gained a new understanding of phishing and social engineering techniques. Before this lesson, I thought that emails, text messages, and phone calls that pretend to be someone from an organization were all simply called phishing. I learned that they have different names depending on how they are carried out and who they target. Vishing is done through phone calls, smishing through SMS, spear phishing targets a specific individual or organization, and whaling targets high-ranking individuals.

I also learned about the psychological tactics used in social engineering. Some of these were already familiar to me or I had even encountered some of them before, such as greed, authority, fear, scarcity, and urgency. However, during the lessons I learned more about how these tactics are intentionally used to influence people's decisions.

I would like to read more about the different social engineering techniques, especially how attackers combine different techniques and psychological tactics to make their attacks more convincing. I am also interested in learning more about how organizations protect their employees from these types of threats.

I did not experience any major confusion or challenges with the topics discussed this week. The concepts were understandable, especially because some of the social engineering tactics were things I had already encountered or was familiar with.

First Week • August 1, 2026

The McCumber Cube, Foundations of Security, and Security Principles

McCumber Cube

Before this discussion, I only viewed information security as protecting systems from hackers and unauthorized access. Since I already have experience in programming, I was familiar with some security practices such as using PDO to prevent SQL injection and validating inputs. However, I did not fully understand where these practices fit in the bigger picture of security.

Learning about the McCumber Cube changed how I look at information protection. It showed me that security is not only about protecting data itself but also defending it while it is stored, being transferred, or being processed by a system. I found it interesting because it provided a clearer way of looking at security problems instead of only focusing on specific attacks.

One concept I would like to learn more about is how the McCumber Cube is applied in real-world systems. I understand the framework, but I am curious about how developers and security professionals use it when designing and evaluating actual systems.

Foundations of Security

The discussion about the CIA Triad and AAA helped me understand the concepts behind many security features that I have encountered before. I was already familiar with authentication systems while developing applications, but learning about AAA gave me a deeper understanding of how authentication, authorization, and accounting work together to control access and monitor user activities.

The CIA Triad also helped me realize that security is not only about preventing unauthorized access. A system also needs to maintain the accuracy of information and ensure that users can access it when needed. This gave me a better understanding of why different security goals need to be considered together when developing systems.

One thing I realized during this discussion was the difference between authentication and authorization. Before this topic, I knew that both were parts of user access systems, but I had not really thought about how they serve different purposes. I learned that authentication focuses on verifying who the user is, while authorization focuses on determining what the user is allowed to access or do.

A concept I would like to learn more about is how CIA and AAA are applied in larger systems, especially how organizations manage different users, permissions, and security requirements.

Security Principles

The discussion on security principles was one of the topics that connected more with my experience as a Computer Science student. My group was assigned Security by Design, and while preparing my presentation, I was able to understand the principle in a more structured way. I already knew that security should be considered during the planning and development of a system, but learning about Security by Design helped me connect this idea to a formal security principle.

Before this discussion, I usually focused on making applications work first and adding security measures when needed. Learning about Security by Design reinforced the importance of considering security early in the development process instead of treating it as something separate from the system.

I became more interested in how different security principles are applied together when developing systems. Principles such as Least Privilege, Need to Know, and Complete Mediation showed me that security is not only about adding security features but also about making careful decisions about user access and system behavior.

One concept I would like to learn more about is how these security principles are applied in real software projects. I want to understand how developers balance security requirements with other factors such as system performance and usability.

Overall, these discussions changed my understanding of information security. I used to think of security mainly as adding protections against attacks, but I now see it as a broader process that involves protecting information, managing access, and considering security throughout system development.
